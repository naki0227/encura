# EnCura 復旧診断（2026-10-20）

App Store 公開版 1.04（2025-12-18 公開）が正常に動かなくなっている原因の一覧です。
オーナー作業の手順は [RELEASE.md](RELEASE.md) にあります。

## 壊れているところ

状態の凡例: **直した** = このブランチのコードで解決 / **オーナー作業** = 手順どおりの作業が必要

| # | 症状 | 原因 | 直し方 | 状態 |
| :- | :--- | :--- | :--- | :--- |
| 1 | 起動はするが、ホーム・展覧会・アーカイブが空、地図投稿もできない | Supabase プロジェクトが一時停止。DB・認証・Storage がすべて止まっている | プロジェクトを復元（または新規作成して SQL を流す）。匿名サインインを有効にする | オーナー作業（RELEASE.md 手順 1） |
| 2 | AI 学芸員のチャットが「Error: …」になる | Gemini キーを `.env` ごとアプリに同梱していた。そのキーは流出のため無効化済み | Gemini 呼び出しを Edge Function `curator` に移し、キーはサーバーのシークレットだけに置く。アプリから `.env` 同梱と `google_generative_ai`・`flutter_dotenv` を削除 | 直した（コード）＋ オーナー作業（新キー設定とデプロイ、手順 2） |
| 3 | Scan & Guide（カメラ解説）が失敗する | 最適化サービスが HTML を 200 で返し、アプリはそれを JPEG として Gemini に送っていた | 応答が `image/*` のときだけ採用し、それ以外は元画像で続行。タイムアウト 15 秒。撮影画像を 2048px・品質 90 に制限して、フォールバック時も送れる大きさにする | 直した |
| 4 | マップ投稿の AI 判定が必ず失敗する | `gemini-2.0-flash-exp` は廃止済み。キーも無効 | 判定を Edge Function に移し、既定モデルを `gemini-3.8-flash` にする（`GEMINI_MODEL` で変更可） | 直した（デプロイは手順 2） |
| 5 | 画像最適化が効かない | Cloud Run サービスが置き換わっている。さらにソースがそのままではビルドできない | `serde_json` を追加し、Dockerfile の Rust を 1.97 にする。`Cargo.lock` をコミット。ローカルでビルドし、2000×1500 → 1024×768 の JPEG が返ることを確認 | 直した（コード）＋ オーナー作業（再デプロイ、手順 3）。再デプロイまでは #3 の対応で元画像のまま動く |
| 6 | 展覧会・今日の一枚・トレンドが 3 月から更新されない | スケジュール実行が無更新で自動停止。Supabase も停止中。GitHub の `GEMINI_API_KEY` も無効の可能性が高い | 点検 workflow が毎日スケジュールを有効にし直す。モデルは `GEMINI_MODEL` で複数指定でき、廃止されたら次を使う | 直した（コード）＋ オーナー作業（Secrets 更新と初回の再有効化、手順 4・6） |
| 7 | `flutter analyze` 警告・`flutter test` 失敗 | `flutter_lints` 未導入、`intl` が暗黙の依存、未使用変数、テンプレのテスト | 依存を追加して警告を解消。テストを実際の処理に合わせて書き直す（7 件） | 直した |
| 8 | CI が何も検査していない | `ci.yml` が echo だけ | analyze・test・Edge Function の `deno check`/`deno lint`・Rust ビルド・クローラーのテスト・未署名の iOS アーカイブ（TestFlight と同じスクリプト）を実行 | 直した |
| 9 | App Store の販売元 URL が旧サイト | `https://enludus.vercel.app` のまま | App Store Connect でサポート URL・マーケティング URL を `https://enludus.com` に変更 | オーナー作業（手順 8） |
| 10 | 利用規約・プライバシーポリシーのリンク先が確認できない | Notion の公開ページ（中身は JS 描画で自動確認できない） | ブラウザで公開状態と内容を確認。AI 処理がサーバー経由になったことを反映するか判断 | オーナー作業（手順 8） |

## コンテンツ（クローラー）の品質

| # | 症状 | 原因 | 直し方 | 状態 |
| :- | :--- | :--- | :--- | :--- |
| 11 | 実在しない展覧会や、違う会期が載る | 日次クローラーが「開催中の美術展を 20 件」とモデルに記憶で答えさせ、そのまま保存していた | Google 検索つきで調べさせ、さらに公式ページ（または検索で使われたページ）に展覧会名が載っていることをクローラー自身が取得して確かめる。確かめられないものは保存しない。出典 URL を `source_url` に保存 | 直した |
| 12 | 展覧会の地図ボタンが、どの展覧会でも東京の中心を開く | 展覧会に位置情報がなく、アプリは読めないときに新宿付近を既定値にしていた。PostgREST が返す EWKB 形式も読めていなかった | クローラーが会場住所を GSI（国土地理院）で座標にして会場と展覧会に保存。アプリは GeoJSON・WKT・EWKB を読み、位置がなければ会場名で地図検索する | 直した |
| 13 | 会場の座標がずれている | 会場の座標をモデルに書かせていた | GSI の住所検索に置き換え、既存の会場を直す `seed_venues.py --relocate` を追加 | 直した ＋ オーナー作業（一度だけ実行、手順 6） |
| 14 | 利用者が投稿した会場マップが消える | 終わった展覧会を毎日削除し、`venue_maps.event_id` の `ON DELETE CASCADE` で投稿も消えていた | 削除をやめる（アプリは終了日で絞り込んでいるので表示は変わらない） | 直した |
| 15 | トレンド記事・季節特集が作り話になる | 「SNS で話題」「今年の見どころ」を出典なしで生成していた | 検索つきで生成し、出典ページに話題の固有名詞が載っていることを確かめたものだけ保存。季節特集はその年の会期が公式発表されるまで書かない | 直した |
| 16 | 記事や今日の一枚の画像が、別の作品になる | Wikimedia Commons の全文検索の 1 件目を使っていた | Wikidata で「その題名」かつ「その作者」の作品を探し、作品の画像（P18）だけを使う。見つからなければ画像なし（今日の一枚は別の作品にする） | 直した |
| 17 | 今日の一枚が同じ絵のまま変わらない | 生成スクリプトが定期実行に入っておらず、在庫が切れると最後の 1 枚が出続ける | 毎日、14 日先まで空いている日を埋める | 直した |
| 18 | 配信モニターが一度も記事を作っていない | チャンネル ID が 23 文字で不正（正しくは 24 文字）。しかも配信タイトルから作品を「推測」し、配信者名を伏せて記事にする作り | スクリプトと週次 workflow を削除（必要なら履歴から戻せます） | 削除した |
| 19 | 失敗しても Actions が緑のまま | どのスクリプトも、エラーを表示して終了コード 0 で終わっていた | 何も保存できなかったときや設定が足りないときは終了コード 1 にする。各ステップは前が失敗しても実行し、ジョブ全体は赤になる | 直した |

あわせて、出典のない記事を入れるだけだった一回限りのスクリプト 2 本（`seed_trends.py` と、会期が 2025 年 1 月に終わった展覧会の記事を入れるもの）を削除しました。
既に DB に入っている過去の記事・展覧会は、出典が確認されていないものを含みます。展覧会は終了日を過ぎると表示されなくなります。トレンド記事は残るので、気になる場合は `source_url` が空の記事を非公開（`is_published = false`）にしてください。

## 埋め込みキーの確認

- 修正後のアプリには、Gemini のキーも `.env` も入りません。アプリが持つのは Supabase の URL と anon キー（公開前提のキーで、RLS で守る）と最適化サービスの URL だけで、どれもビルド時に `--dart-define` で渡します。
- リポジトリと履歴（取得した範囲）に `AIza…` 形式のキーはありません。`.env` がコミットされた形跡もありません。
- 公開中の 1.04 のバイナリには無効化済みのキーが入っています。キーは無効なので悪用はできませんが、1.0.5 の公開後は 1.04 を配信し続ける理由はありません。

## そのままにしたもの（今回の範囲外）

- `flutter_markdown` は提供終了（後継は `flutter_markdown_plus`）。今のところビルド・動作に問題はありません。
- `venue_maps` テーブルと Storage は匿名でも INSERT できるポリシーのまま（以前からの設計）。
- Python クローラーは提供終了した `google-generativeai` SDK をやめ、Gemini の REST API を直接呼ぶ形にしました（SDK の改名・終了に左右されないため）。
